Перечисление натуральных чисел с различными взаимодополняющими цифрами

1. Проект и дисциплина

Учебная работа по дисциплине «Методы комбинаторных вычислений», МГТУ им. Н.Э. Баумана. Программа на ISO C11 перечисляет натуральные числа с различными цифрами, среди которых есть хотя бы одна взаимодополняющая пара. Результаты поступают в стандартный вывод в возрастающем порядке.

2. Исходная формулировка задания

Перечислить все натуральные числа m из 10-х разрядов, в которых цифры попарно различны и значения разрядов хоть в 1 паре дополняют друг друга.

При программной реализации этих перечислений значения параметров должны задавать опции командной строки с контролем допустимости их величин. Кроме того, следует предусмотреть значения параметров по умолчанию, если их опции не заданы, и стандартный вывод результатов.

3. Математическая постановка и принятые допущения

Формулировка неоднозначна: m может обозначать само число или количество цифр; «из 10-х разрядов» может означать десятичную запись либо ровно десять разрядов; сумма дополнения не названа. Эти вопросы нельзя разрешить одним выбором алгоритма.

В этой работе принята рабочая модель проекта, а не доказанное намерение преподавателя:

D={0,1,…,9},2≤m≤10,S∈{9,10}.

Нужно перечислить все векторы X=(x1,…,xm), для которых

xi∈D;i≠j⇒xi≠xj;x1≠0;∃i<j: xi+xj=S.

Вектор задаёт натуральное число N(X)=∑i=1mxi10m−i. Число и длина обозначены разными буквами, чтобы устранить перегрузку исходного m.

Дополняются цифры, а не величины xi10m−i. Позиции пары произвольны: соседство, симметрия и расположение на краях не требуются. Достаточно хотя бы одной пары. Несколько пар не создают нескольких результатов.

При S=9 пары: {0,9}, {1,8}, {2,7}, {3,6}, {4,5}. При S=10: {1,9}, {2,8}, {3,7}, {4,6}. Пара {5,5} запрещена различием цифр; 0 и 5 остаются без партнёров.

Если преподаватель требует строго десятизначные числа, запускают --digits 10. Значения по умолчанию m=4, S=10 являются принятыми проектными решениями. Они не приписываются учебным пособиям. В просмотренных разделах и заданиях 7–8 лабораторной определения нужной суммы дополнения нет.

В формулах далее m обозначает длину записи, S — сумму пары, Q(m,S) — количество результатов. Прописная M в синтаксисе CLI является обозначением того же параметра длины.

5. Почему используются размещения без повторений

Сочетание задаёт только состав выбранных цифр. Здесь 1289 и 9821 являются разными числами, поэтому порядок существенен. Нужно размещение без повторений из 10 цифр по m.

По правилу произведения выбор позиций имеет соответственно 10, 9, ..., 10−m+1 вариантов:

A10m=10·9⋯(10−m+1)=10!(10−m)!.

То же следует из выбора m-элементного сочетания и его m! порядков: A10m=C10mm!. Это соответствует определениям [1, раздел о размещениях] и [5, §1.2.1].

Без ограничения суммы, но с запретом первого нуля, число кандидатов равно

Bm=A10m−A9m−1=99!(10−m)!.

Первое слагаемое учитывает все размещения. Второе фиксирует ноль слева и размещает оставшиеся m−1 цифр из девяти.

При m=10 выбираются все цифры, поэтому размещения становятся перестановками:

A1010=10!=3628800;B10=10!−9!=9·9!=3265920.

Пары обеих сумм при использовании всех цифр существуют. Следовательно, последнее значение является числом результатов для обеих сумм.

7. Лексикографический метод перечисления

Для двух различных векторов одинаковой длины сравнивают первую позицию, в которой они различаются. Меньшим считается вектор с меньшей цифрой в этой позиции. Например, 019 < 021 < 023. Такое упорядочивание позволяет определять непосредственного преемника без хранения всех предыдущих объектов.

Переход к следующей полной перестановке

Функция next_permutation реализует [1, PDF 48; 3, PDF 4]:

  1. Найти справа самый правый индекс i с pi<pi+1.
  2. Если его нет, вся перестановка убывает: следующей нет.
  3. В убывающем правом хвосте найти справа первый элемент больше pi. Это минимальный из элементов, больших pi.
  4. Обменять эти элементы.
  5. Развернуть хвост после i, получая его возрастающий порядок.

В C индексы начинаются с 0. Используется строгое сравнение: элементы по контракту попарно различны. При отсутствии перехода массив не изменяется.

Переход применяется к полной перестановке десяти цифр. Для размещения длины m используется дополнительная организация: текущий префикс ставится в конец своего блока полных перестановок. Её точный смысл объясняется далее и доказывается в разделе 15.

8. Алгоритмические операции и ручная трассировка

Начальная конфигурация

Для цифр 0..9 первое размещение имеет вид (0,1,...,m−1). Оно содержит ведущий ноль, но генератор обязан перечислять весь класс размещений. Фильтр натуральности применяется отдельно.

Замена алфавита 1..10 из лекции на 0..9 сохраняет все отношения порядка. При m=10 дополнение пусто, и переход становится обычной следующей перестановкой. Эти специализации не меняют принцип алгоритма.

Дополнение, переход и усечение

Функция next_arrangement буквально выполняет три операции источника:

X→+(X,sort↓(D⧵X))→LP′→−(p1′,…,pm′).

Дополнение строится заново на каждом шаге. Хвост после предыдущего перехода не переиспользуется: он мог оказаться возрастающим. Отбрасывание хвоста означает копирование только первых m элементов, а не сохранение всех его перестановок.

enum { BASE = 10 }; задаёт целочисленную константу времени компиляции. Это позволяет использовать BASE как размер обычного массива без выделения памяти в куче.

Options хранит четыре независимых параметра: длину, сумму, флаг подсчёта и флаг справки. Тип создан через typedef struct, поэтому далее достаточно имени Options. Это не класс, у структуры нет методов или скрытого состояния.

static перед вспомогательными функциями означает внутреннее связывание: функции доступны внутри этого файла. Оно не превращает их локальные массивы в глобальные или статические переменные.

10.2. parse_integer: строки 18–37

Контракт: получить строку и разрешённый диапазон; при успехе записать целое по адресу value, при ошибке вернуть false.

Проверки выполняются по порядку:

  1. *text == '\0' означает пустую строку. Она отклоняется до преобразования.
  2. Цикл по указателю p проверяет каждый байт. Разрешены только символы от '0' до '9'. Поэтому +4, -4, пробелы, 4.0, 0x4, буквы и цифры других алфавитов не принимаются.
  3. errno = 0 очищает прежнюю ошибку. Иначе старое значение ERANGE могло бы ошибочно дисквалифицировать корректное преобразование.
  4. strtol(text, &end, 10) читает десятичное long. Адрес &end нужен, чтобы функция сообщила, где остановилась.
  5. ERANGE означает переполнение; ненулевой символ по end — непрочитанный хвост. Затем проверяются границы minimum и maximum.
  6. Только после всех проверок значение приводится к int и записывается через *value.

Приведение к int безопасно: принятый диапазон не превосходит 10. Ведущие нули в значении параметра разрешены: строка 04 задаёт число 4. Это не разрешает ведущий ноль в перечисляемых числах: параметры и результаты — разные сущности.

10.3. parse_options: строки 39–85

argc содержит число аргументов вместе с именем программы. argv — массив указателей на строки. Поэтому разбор начинается с индекса 1.

Выражение (Options){4, 10, false, false} — составной литерал структуры. Через *options сразу устанавливаются все значения по умолчанию. Программа не зависит от неинициализированных полей.

strcmp(a, b) == 0 означает равенство строк. Сравнение указателей через == вместо strcmp не проверяло бы содержимое аргумента.

У каждой опции есть свой путь:

ОпцияЧто делает разбор
--helpТребует argc == 2, затем выставляет флаг. Совместный вызов с любыми аргументами — ошибка
--count-onlyПроверяет, что флаг ещё не установлен, затем устанавливает его
--digits / --sumВыбирает соответствующее поле и признак повтора, проверяет наличие следующего аргумента, вызывает parse_integer
Всё остальноеДиагностика неизвестной опции или лишнего позиционного аргумента

Для числовых опций локальный bool *seen указывает либо на seen_digits, либо на seen_sum. Аналогично int *value указывает на поле длины либо суммы. Так одна короткая ветвь выполняет одинаковые проверки, не создавая отдельной системы регистрации опций.

argv[++i] сначала увеличивает индекс, затем получает значение опции. После окончания итерации внешний цикл увеличит индекс ещё раз и перейдёт к следующему имени опции. Перед этим проверено, что значение существует.

При любой ошибке функция сразу возвращает false. main тогда завершится с кодом 2. Ни начальное размещение, ни цикл перечисления ещё не создавались, поэтому ошибочный вызов не успевает вывести часть результатов.

10.4. next_permutation: строки 87–111

Параметр int permutation[BASE] в объявлении функции передаётся как указатель на начало массива. Отдельная копия массива автоматически не создаётся: обмены меняют переданный массив.

Первая проверка ищет pivot — последний подъём. Индекс начинается с BASE - 2, то есть 8: последний сравниваемый сосед находится в ячейке 9. Условие pivot >= 0 && ... использует короткое замыкание: при отрицательном индексе обращение к массиву справа от && не выполняется.

В алгоритме общего назначения, допускающем повторяющиеся элементы, часто используют сравнения >= и <=. Здесь элементы по контракту различны, поэтому достаточно > и <: равных соседей или равной замены быть не может.

Если pivot не найден, весь массив убывает. Возврат false происходит до обменов, исходная перестановка остаётся нетронутой.

Затем successor просматривает хвост справа налево. Хвост убывает, значит первый найденный элемент больше pivot является минимальной допустимой заменой. Нужный элемент существует: хотя бы сосед справа от pivot больше его по определению подъёма.

Переменная temporary обеспечивает обмен без потери старого значения. После обмена два индекса left и right идут навстречу друг другу и разворачивают хвост. На центральном элементе нечётного хвоста обмен не нужен, поэтому условие строгое: left < right.

Пример: 0198765432 → pivot равен 1 на позиции 1 → минимальная замена 2 → после обмена 0298765431 → после разворота хвоста 0213456789. Первые три цифры меняются с 019 на 021.

10.5. next_arrangement: строки 113–138

used[10] изначально полностью заполнен false. Первый цикл копирует m текущих цифр во временную перестановку и отмечает их присутствие. Индекс used[arrangement[i]] безопасен: инвариант гарантирует цифры от 0 до 9.

position = length указывает на первое свободное место после префикса. Цикл digit = 9 ... 0 добавляет только неотмеченные цифры. Их ровно 10 - length, поэтому после дополнения записаны ровно десять ячеек, а индекс не выходит за границу.

Временный массив permutation не инициализируется нулями: это не требуется, поскольку первые m ячеек записывает первый цикл, а остальные 10-m — второй. До чтения заполнена каждая ячейка.

Вызов next_permutation выполняет лекционную операцию L. Если преемника нет, внешний массив размещения не меняется. Если преемник есть, копируются только первые m ячеек. Так усечение реализуется без удаления элементов или динамической памяти.

При m=10 второй цикл ничего не добавляет, поскольку все цифры отмечены. Остальные действия остаются теми же. Отдельного алгоритма для этого случая нет.

10.6. has_complementary_pair: строки 140–151

Внешний индекс i выбирает первую позицию пары, внутренний j начинается с i + 1. Поэтому каждая неупорядоченная пара различных позиций проверяется один раз; позиция не сравнивается сама с собой.

Проверяется именно digits[i] + digits[j] == sum. Расстояние между позициями не участвует в условии. Возврат true при первой найденной паре означает «существует хотя бы одна». Он не отбрасывает числа с двумя или более парами.

Если оба цикла завершились без успеха, возвращается false. const перед массивом показывает, что функция только читает цифры.

10.7. write_number: строки 153–163

Максимум нужно записать 10 цифр и перевод строки, поэтому достаточно char line[11]. Выражение '0' + digits[i] переводит числовое значение цифры в её символ. Арифметика десятизначного числа при этом вообще не вычисляется.

В конце добавляется \n. Завершающий нулевой байт не требуется: это не строка для printf("%s", ...), а буфер известной длины для fwrite. Вызов передаёт размер элемента 1 и число элементов length + 1; возврат должен совпасть с этим количеством.

Такой вывод безопасен для 9876543210, которое не помещается в 32-битный signed int. В int хранятся только отдельные цифры и небольшие индексы.

10.8. write_help: строки 165–183

Соседние строковые литералы C автоматически объединяются компилятором. Обратный слеш n задаёт перевод строки внутри текста. fputs выводит справку; неотрицательный возврат означает успешное принятие данных библиотекой stdio. Финальная проверка fflush всё равно нужна: запись могла пока попасть только в буфер.

Справка перечисляет назначение, синтаксис, диапазоны, значения по умолчанию, запрет повторов, правило отдельного --help, формат вывода и команды-примеры. Английский текст справки не влияет на математическую модель или формат числовых результатов.

10.9. main: строки 185–223

Порядок действий важен:

  1. Создать локальные параметры и полностью проверить CLI. При ошибке немедленно вернуть 2.
  2. Для отдельного --help вывести справку, затем перейти к общей проверке записи.
  3. Для обычного режима заполнить первые m цифр значениями 0,1,...,m−1. Полная нулевая инициализация массива также делает состояние явным для GCC.
  4. Создать нулевой uint64_t count и войти в do ... while.
  5. Сначала проверить ненулевую первую цифру. Благодаря && проверка пары для ведущего нуля не вызывается.
  6. Если есть пара, увеличить счётчик. Вывести число только при выключенном count_only.
  7. При ошибке записи установить output_ok = false и прекратить перебор. Успешное количество после частично неудачного вывода не печатается.
  8. В условии цикла построить следующее размещение. Если его нет, цикл закончен.
  9. В режиме подсчёта вывести накопленное количество с форматом PRIu64.
  10. В обоих режимах проверить fflush(stdout). При ошибке вернуть 1; иначе вернуть 0.

do ... while выбран потому, что начальная конфигурация уже существует и должна быть рассмотрена до первого перехода. Обычный цикл с переходом до обработки мог бы пропустить её. Хотя первое размещение отбрасывается по ведущему нулю, корректность генератора от этого не должна зависеть.

Для обычного вывода выражение !options.count_only && !write_number(...) не вызывает write_number, когда включён подсчёт. Но сам цикл и next_arrangement работают в обоих режимах. Поэтому --count-only — отключение вывода чисел, а не замена перечисления формулой.

Строка printf("%" PRIu64 "\n", count) после препроцессора превращается в подходящий платформе формат. Нельзя без проверки предполагать, что uint64_t обязательно соответствует unsigned long long.

10.10. Полный исходный код main.c

Листинг совпадает с принятым исходником побайтно; номера строк в заголовках относятся к нему.

c
#include <errno.h>
#include <inttypes.h>
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

enum { BASE = 10 };

typedef struct {
    int digits;
    int sum;
    bool count_only;
    bool help;
} Options;

/* Accept only nonempty ASCII decimal strings; reject overflow and range errors. */
static bool parse_integer(const char *text, int minimum, int maximum, int *value)
{
    if (*text == '\0') {
        return false;
    }
    for (const char *p = text; *p != '\0'; ++p) {
        if (*p < '0' || *p > '9') {
            return false;
        }
    }
    errno = 0;
    char *end = NULL;
    long parsed = strtol(text, &end, 10);
    if (errno == ERANGE || *end != '\0' || parsed < minimum || parsed > maximum) {
        return false;
    }
    *value = (int)parsed;
    return true;
}

/* Validate every argument before enumeration or help output begins. */
static bool parse_options(int argc, char **argv, Options *options)
{
    bool seen_digits = false;
    bool seen_sum = false;
    *options = (Options){4, 10, false, false};

    for (int i = 1; i < argc; ++i) {
        const char *arg = argv[i];
        if (strcmp(arg, "--help") == 0) {
            if (argc != 2) {
                fputs("error: --help must be used alone\n", stderr);
                return false;
            }
            options->help = true;
        } else if (strcmp(arg, "--count-only") == 0) {
            if (options->count_only) {
                fputs("error: duplicate --count-only\n", stderr);
                return false;
            }
            options->count_only = true;
        } else if (strcmp(arg, "--digits") == 0 || strcmp(arg, "--sum") == 0) {
            bool is_digits = strcmp(arg, "--digits") == 0;
            bool *seen = is_digits ? &seen_digits : &seen_sum;
            if (*seen) {
                fprintf(stderr, "error: duplicate %s\n", arg);
                return false;
            }
            *seen = true;
            if (i + 1 == argc) {
                fprintf(stderr, "error: %s requires a value\n", arg);
                return false;
            }
            int *value = is_digits ? &options->digits : &options->sum;
            int minimum = is_digits ? 2 : 9;
            if (!parse_integer(argv[++i], minimum, 10, value)) {
                fprintf(stderr, "error: %s requires decimal digits in range %s\n",
                        arg, is_digits ? "2..10" : "9..10");
                return false;
            }
        } else {
            fprintf(stderr, "error: unknown option or positional argument: %s\n", arg);
            return false;
        }
    }
    return true;
}

/* Replace a distinct-element permutation by its immediate lexicographic successor.
 * Return false without modifying it when its order is entirely decreasing. */
static bool next_permutation(int permutation[BASE])
{
    int pivot = BASE - 2;
    while (pivot >= 0 && permutation[pivot] > permutation[pivot + 1]) {
        --pivot;
    }
    if (pivot < 0) {
        return false;
    }
    int successor = BASE - 1;
    while (permutation[successor] < permutation[pivot]) {
        --successor;
    }
    int temporary = permutation[pivot];
    permutation[pivot] = permutation[successor];
    permutation[successor] = temporary;
    for (int left = pivot + 1, right = BASE - 1; left < right; ++left, --right) {
        temporary = permutation[left];
        permutation[left] = permutation[right];
        permutation[right] = temporary;
    }
    return true;
}

/* Precondition: 2 <= length <= 10, distinct digits in 0..9.
 * Lecture's (+, L, -): append missing digits in decreasing order,
 * take next full permutation, retain its first length digits.
 * On false, arrangement remains unchanged. */
static bool next_arrangement(int arrangement[BASE], int length)
{
    bool used[BASE] = {false};
    int permutation[BASE];
    for (int i = 0; i < length; ++i) {
        permutation[i] = arrangement[i];
        used[arrangement[i]] = true;
    }
    int position = length;
    for (int digit = BASE - 1; digit >= 0; --digit) {
        if (!used[digit]) {
            permutation[position++] = digit;
        }
    }
    if (!next_permutation(permutation)) {
        return false;
    }
    for (int i = 0; i < length; ++i) {
        arrangement[i] = permutation[i];
    }
    return true;
}

/* Test existence, not number, adjacency, or positions of complementary pairs. */
static bool has_complementary_pair(const int digits[BASE], int length, int sum)
{
    for (int i = 0; i < length; ++i) {
        for (int j = i + 1; j < length; ++j) {
            if (digits[i] + digits[j] == sum) {
                return true;
            }
        }
    }
    return false;
}

/* Emit digits directly, including ten-digit values beyond signed 32-bit range. */
static bool write_number(const int digits[BASE], int length)
{
    char line[BASE + 1];
    for (int i = 0; i < length; ++i) {
        line[i] = (char)('0' + digits[i]);
    }
    line[length] = '\n';
    size_t size = (size_t)length + 1;
    return fwrite(line, 1, size, stdout) == size;
}

static bool write_help(void)
{
    return fputs(
        "Enumerate decimal natural numbers with distinct digits and at least\n"
        "one pair of positions i < j whose digits sum to S. Output is ascending.\n"
        "Usage: mkv_numbers [--digits M] [--sum S] [--count-only]\n"
        "       mkv_numbers --help\n"
        "  --digits M     Number of decimal digits: 2..10 (default: 4).\n"
        "  --sum S        Complementary digit sum: 9 or 10 (default: 10).\n"
        "  --count-only   Enumerate all candidates; print only result count.\n"
        "  --help         Show this help; must be used alone.\n"
        "Values: nonempty ASCII decimal digit strings, separate arguments.\n"
        "Leading zeroes in parameter values are accepted. No repeated options.\n"
        "Output: one number per line, or one count followed by a newline.\n"
        "Examples:\n"
        "  ./mkv_numbers --digits 2 --sum 10\n"
        "  ./mkv_numbers --digits 4 --sum 10 --count-only\n"
        "  ./mkv_numbers --digits 10 --sum 9 > numbers.txt\n", stdout) >= 0;
}

int main(int argc, char **argv)
{
    Options options;
    if (!parse_options(argc, argv, &options)) {
        return 2;
    }
    bool output_ok = true;
    if (options.help) {
        output_ok = write_help();
    } else {
        int digits[BASE] = {0};
        for (int i = 0; i < options.digits; ++i) {
            digits[i] = i;
        }
        uint64_t count = 0;
        do {
            if (digits[0] != 0 &&
                has_complementary_pair(digits, options.digits, options.sum)) {
                ++count;
                if (!options.count_only && !write_number(digits, options.digits)) {
                    output_ok = false;
                    break;
                }
            }
        } while (next_arrangement(digits, options.digits));
        if (options.count_only) {
            output_ok = printf("%" PRIu64 "\n", count) >= 0;
        }
    }
    /* Buffered writes can fail only when the final buffer is flushed. */
    if (fflush(stdout) == EOF) {
        output_ok = false;
    }
    if (!output_ok) {
        fputs("error: cannot write to stdout\n", stderr);
        return 1;
    }
    return 0;
}

11. Последовательность выполнения программы

При запуске операционная система передаёт argc и argv в main. Сначала целиком проверяются параметры; затем выбирается справка либо перечисление. При перечислении состояние начинается с минимального размещения, обрабатывается фильтрами, при необходимости выводится и заменяется следующим. Отсутствие преемника завершает цикл. Последними выполняются вывод счётчика, если он запрошен, и проверка отложенной записи.

Схема вызовов и ответственности

text
main
├── parse_options
│   └── parse_integer
├── write_help                    [только отдельный --help]
├── цикл всех размещений
│   ├── проверка первой цифры
│   ├── has_complementary_pair
│   ├── write_number              [когда count-only выключен]
│   └── next_arrangement
│       └── next_permutation
├── printf(count)                 [когда count-only включён]
└── fflush(stdout) и код завершения

Генератор отвечает за класс размещений и порядок, фильтры — за ограничения задачи, вывод — за формат и ошибки записи. Это разделение позволяет доказывать каждую часть отдельно и не смешивать алгоритм перечисления с независимой формулой количества.

Пример пути одного результата

Для --digits 2 --sum 10 параметры становятся (2,10,false,false). Генератор начинает с 01; размещения с первым нулём не проходят первый фильтр. После 09 идёт 10: ведущего нуля нет, но сумма цифр равна 1. Далее проверяются 12, 13, …, 19; у 19 сумма равна 10, счётчик увеличивается и выводится 19 . Последующие подходящие размещения дают 28, 37 и остальные строки. В режиме --count-only путь тот же, но write_number не вызывается; после конца цикла печатается 8.

При отдельном --help генератор вообще не запускается. При неверных параметрах программа заканчивается ещё до инициализации размещения.

15. Доказательство корректности алгоритма

Это доказательство применительно к программе является нашим выводом из лекционного алгоритма.

Лемма 1. Корректность перехода перестановки

Пусть i — самый правый подъём. Суффикс после i строго убывает, то есть является наибольшим порядком своих элементов. Поэтому следующую большую перестановку невозможно получить изменением только этого суффикса.

Чтобы изменение было минимально, нужно сохранить позиции до i и увеличить элемент именно в позиции i. Среди допустимых замен выбирается минимальный больший элемент. В убывающем суффиксе это первый больший элемент при просмотре справа.

После обмена суффикс остаётся убывающим: справа от выбранного элемента были только элементы меньше прежнего pivot, слева — элементы больше выбранного. Его разворот даёт наименьший возможный хвост. Полученная перестановка больше исходной, и никакая другая не может лежать между ними: более раннее изменение больше, меньшая допустимая замена отсутствует, меньший хвост невозможен. Если подъёма нет, исходная перестановка глобально наибольшая.

Лемма 2. Корректность дополнения по убыванию

Все полные перестановки с фиксированным m-префиксом X образуют один непрерывный блок лексиграфического порядка. Действительно, сравнение с перестановкой другого префикса определяется внутри первых m позиций и не зависит от хвостов.

Дополнение отсутствующими элементами по убыванию является последней перестановкой блока X. Её непосредственный преемник, если существует, является первой перестановкой следующего блока. Префикс этого преемника и есть непосредственно следующее размещение. При пропуске какого-либо размещения между блоками существовала бы полная перестановка между двумя непосредственными преемниками, что противоречит лемме 1.

При дополнении по возрастанию была бы взята первая перестановка текущего блока; следующий переход мог бы изменить только хвост и сохранить X. Поэтому порядок убывания принципиален. При m=10 каждый блок одноэлементный, и лемма остаётся верной.

Инвариант длины и различия

Начальное X имеет ровно m различных цифр из D и является наименьшим размещением: сначала берётся наименьшая возможная цифра, затем наименьшая ещё не использованная, и так далее.

Массив used отмечает его цифры. Дополнение добавляет каждый отсутствующий элемент ровно один раз. Получается перестановка всех десяти цифр; обмен и разворот сохраняют её состав и различие. Первые m элементов снова являются размещением требуемой длины. Внешний массив хранит десять ячеек, но значимы только первые m.

Корректность фильтров и единственность результата

Фильтр digits[0] != 0 необходим и достаточен для m-значности десятичной записи: остальные цифры уже допустимы. Ноль внутри числа разрешён.

Функция has_complementary_pair рассматривает все m(m−1)/2 пар различных позиций i<j. Она возвращает true при первом равенстве суммы S и false только после проверки всех пар. Значит, она реализует квантор существования. Нельзя получить пару из одной позиции, а {5,5} невозможно по инварианту различия.

Каждый X обрабатывается один раз и имеет единственный вызов вывода. Поэтому 1289 при S=10, несмотря на пары 1+9 и 2+8, выводится один раз. 1029 показывает допустимость несоседней пары.

У каждого допустимого натурального числа есть единственная десятичная запись без ведущего нуля, и она является одним из перечисляемых размещений. Фильтры принимают её. Обратно, каждый выведенный вектор удовлетворяет всем четырём условиям. Получена биекция между допустимыми числами и строками вывода.

Числовой порядок

Пусть векторы равной длины впервые отличаются в позиции k, причём xk<yk. Вклад отличия в этой позиции не меньше 10m−k, тогда как абсолютная разность вкладов всех младших позиций не больше 10m−k−1. Поэтому N(X)<N(Y).

Следовательно, лексиграфический порядок совпадает с числовым. Удаление части членов строго возрастающей последовательности оставляет её строго возрастающей. Фильтрация не нарушает порядок и не требует сортировки.

16. Доказательство полноты и завершения перечисления

Начинаем с минимального размещения. По лемме 2 раздела 15 каждый успешный шаг даёт ровно непосредственного преемника. Индукцией перечисляются все размещения по порядку, без пропусков и повторений. Строгое увеличение исключает возврат к прежнему объекту.

Класс конечен и содержит A10m объектов. Последний имеет вид (9,8,...,10−m). Вместе с убывающим дополнением он образует 9876543210, у которого нет подъёма. Алгоритм завершается после обработки последнего размещения. Цикл do ... while обрабатывает и первое, и последнее размещение, а затем проверяет переход; ошибка пропуска границ отсутствует.

Пусть Y — произвольная допустимая десятичная запись длины m. Она является размещением из D, следовательно, принадлежит конечной цепочке от минимального до максимального размещения. Переход к непосредственному преемнику не может перескочить Y. При её обработке оба фильтра истинны. Поэтому Y выводится, либо учитывается счётчиком в режиме подсчёта. Так полнота генератора вместе с точностью фильтров даёт полноту решения исходной рабочей задачи.

17. Доказательство отсутствия повторов

Каждый успешный переход next_arrangement строго увеличивает размещение в лексикографическом порядке. Если бы некоторое размещение встретилось дважды, между этими появлениями существовала бы строго возрастающая цепочка, начинающаяся и заканчивающаяся одним объектом. Это невозможно. Следовательно, генератор не повторяет кандидатов.

При обработке одного размещения счётчик увеличивается не более одного раза и write_number вызывается не более одного раза. has_complementary_pair возвращает логический признак при первой найденной паре, а не запускает вывод для каждой пары. Поэтому несколько подходящих пар внутри одного числа не создают дополнительных строк.

Разные допустимые размещения длины m без первого нуля задают разные натуральные числа: десятичная запись такого числа единственна. Значит, различие векторов сохраняется и после вывода символов. Совместно с полнотой раздела 16 это означает, что каждое допустимое число выводится ровно один раз.

Пусть T — все m-элементные подмножества D, содержащие хотя бы одну пару с суммой S. Тогда

Q(m,S)=∑T∈T(m!−1{0∈T}(m−1)!).

Этот эталон перебирает не больше C105=252 множеств на одно значение m и не использует переходов C-программы. По смыслу он опирается на связь сочетаний и перестановок [1, PDF 99–100; 5, §1.2.1].

Пороговые свойства

Для S=9 множество D разбито на пять непересекающихся пар. Чтобы не иметь подходящей пары, из каждой можно выбрать не больше одной цифры, то есть максимум пять цифр. Любые шесть различных цифр по принципу Дирихле содержат пару. Граница точна: {0,1,2,3,4} не содержит пары с суммой 9.

Для S=10 имеются четыре непересекающиеся пары и две отдельные цифры 0 и 5. Без подходящей пары можно выбрать максимум 4+2=6 цифр. Любые семь различных цифр содержат пару. Граница точна: {0,1,2,3,4,5} пары с суммой 10 не содержит; например, 102345 не проходит фильтр.

При m=10 содержатся все цифры: для S=9 существуют все пять пар, для S=10 все четыре. Однако в программе проверка пары не заменена специальным ответом даже за порогом: используется один и тот же алгоритм для всех m.

19. Формула включения-исключения

Теоретическая основа — [5–7, гл. 2, §2.1, формула (2.1), §2.2, теорема 2.1]. Для каждой допустимой пары зададим событие Ei: число содержит обе её цифры. Нужна мощность объединения, а не сумма мощностей событий:

Q(m,S)=|⋃i=1kEi|=∑∅≠J⊆{1,…,k}(−1)|J|+1|⋂i∈JEi|.

Если число содержит t подходящих пар, его суммарный вес равен ∑j=1t(−1)j+1Ctj=1−(1−1)t=1. Так исключается многократный подсчёт.

Пары попарно не пересекаются. Зафиксируем j обязательных пар: они требуют r=2j разных цифр. Обозначим z=1, если среди обязательных цифр есть ноль, иначе z=0. Число допустимых чисел, содержащих фиксированное обязательное множество:

Fm(r,z)=C10−rm−rm!−{C10−rm−r(m−1)!,z=1;C9−rm−r−1(m−1)!,z=0.

Полагаем Cnq=0, если q<0 или q>n; невозможные пересечения дают 0. В частности, F_m(r,z)=0 при r>m, а случай r=10,z=0 невозможен, поскольку все десять цифр включают ноль; для него также принимается значение 0, без вычисления сочетания с отрицательным размером множества. Сначала выбираем остальные m−r цифр и переставляем все m цифр. Затем вычитаем записи с первым нулём. Если ноль обязателен, он есть в каждом выбранном множестве. Иначе его нужно отдельно выбрать из необязательных цифр; остаются 9−r ненулевых вариантов для m−r−1 мест множества. После фиксации нуля слева остаётся (m−1)! порядков.

Для S=10 ни одна пара не содержит 0, поэтому

Q(m,10)=∑j=14(−1)j+1C4jFm(2j,0).

Для S=9 одна пара {0,9} содержит 0. Группы из j пар разделяются на не содержащие эту пару и содержащие её:

Q(m,9)=∑j=15(−1)j+1[C4jFm(2j,0)+C4j−1Fm(2j,1)].

Например, при m=4: F4(2,0)=28·24−7·6=630, F4(2,1)=28·18=504, F4(4,0)=24, F4(4,1)=18. Тогда

Q(4,10)=4·630−6·24=2376;Q(4,9)=4·630+504−6·24−4·18=2808.

Эти специализированные формулы выведены здесь, а не заимствованы в готовом виде из лекций. Основная C-программа их не использует.

20. Вычислительная сложность и память

Пусть n — размер алфавита, m — длина, A=n!/(n−m)!, Q — число выведенных результатов.

Инициализация стоит O(m). Построение отметок и дополнения, поиск pivot и замены, разворот и копирование стоят O(n) в худшем случае на переход. Проверка первого нуля O(1), пары — O(m²), точнее не больше m(m−1)/2 сложений и сравнений. Ранний выход может уменьшить фактическую работу, но не худшую оценку. Генерируются все A размещений, включая ведущие нули.

Вычисления без внешнего вывода требуют O(A·(n+m²)). Формирование строк требует дополнительно O(Qm), а передаваемый объём равен Q·(m+1) байтам для ASCII и LF. Физическое время записи зависит от терминала, трубы, файла и файловой системы; оно не определяется одной асимптотикой генератора. --count-only убирает Q строк, но сохраняет весь перебор и проверку пары.

Для фиксированного n=10 число проверок пары не больше 45, переход использует только десять элементов; время пропорционально числу размещений с небольшой постоянной. При m=10 A=3628800, Q=3265920; вывод имеет 35 925 120 байт для каждой суммы, без сохранения этого объёма внутри программы.

Основные данные C: массив текущего размещения из 10 int, временная перестановка из 10 int, 10 отметок bool, буфер строки из 11 char, локальные параметры и счётчик. Используется O(n) дополнительной памяти, при фиксированных десяти цифрах — O(1). Буфер stdio не растёт с количеством результатов. Стек имеет постоянную глубину, malloc и хранение всех результатов не нужны.

C11 выбран из-за прозрачных массивов, явных переходов и простого стандартного интерфейса ввода-вывода. Это не утверждение о превосходстве C над C++ по скорости при одинаковом алгоритме.

Устройство независимых эталонов на этапе разработки

subset_count перебирает itertools.combinations(range(10), length). Порядок элементов множества на этом этапе несущественен. Для каждого подходящего состава добавляется m! или m!-(m-1)!. Эта функция не знает, как C строит следующий вектор.

intersection_count вычисляет размер одного пересечения событий обязательных пар с учётом наличия нуля. inclusion_exclusion_count группирует пересечения по количеству пар. Это другой способ подсчёта, чем перечисление всех подмножеств.

reference_lines получает упорядоченные кортежи от itertools.permutations, отдельно проверяет первый ноль и существование пары. Возвращаются именно байтовые строки с LF, поэтому сравнение замечает даже лишний заголовок, пробел, пропущенный перевод строки или неверный порядок.

Константа CONTROL хранит заданную таблицу как третий ориентир. Она не используется для генерации эталона. Если бы таблица оказалась неверной, сравнение с двумя вычисляемыми формулами показало бы расхождение.

Инварианты одной строки

check_line проверяет длину m+1 вместе с LF, цифры ASCII, ненулевую первую цифру, m различных символов, подходящую пару, строгое увеличение и диапазон [10^(m−1), 10^m). В Python обход байтов возвращает их числовые коды, поэтому в проверке пары сравнивают сумму кодов с S + 2*ord('0').

Для m=6..9 достаточно совокупности трёх фактов: все выведенные элементы допустимы, они различны, их количество равно независимо найденному размеру всего допустимого множества. Конечное подмножество с той же мощностью совпадает со всем множеством. Это объясняет, почему потоковая проверка вместе с формулой устанавливает полноту, даже без отдельного списка всех эталонных строк этих длин.

Для m=10 выполняется более сильная непосредственная проверка: следующая строка C сравнивается со следующим элементом независимого итератора Python. После конца C дополнительно проверяется, что и Python закончился. Условия на сумму гарантированы использованием всех цифр, но каждая полученная строка всё равно проходит обычную проверку пары.

На этапе разработки большой поток проверялся в полном режиме. В сокращённом режиме восьмая группа пропускалась; такой запуск не считался полной проверкой stdout.

Память, stderr и завершение дочерних процессов

Малые последовательности можно сравнивать в памяти: максимум 23 760 строк. Большие потоки читаются через Popen(..., stdout=PIPE) по одной строке. Хранить миллионы результатов не требуется.

stderr большого запуска направляется во временный файл, затем проверяется на пустоту. Это не позволяет непрочитанной трубе stderr заблокировать дочерний процесс. В finally ещё работающий процесс прекращается и ожидается его завершение, поэтому провал утверждения не оставляет генератор работающим в фоне.

Санитайзер обнаруживает только ошибки на реально выполненных путях; он не заменяет доказательство полноты или сравнение результатов. Математический эталон тоже не заменяет проверку безопасности обращений к памяти. Здесь способы дополняют друг друга.

Сборка без предупреждений показывает принятие исходника конкретным компилятором. Статический анализ и санитайзеры проверяют реализацию на доступных путях. Сравнение последовательностей и инварианты проверяют содержимое потока, независимые формулы — мощность множества, а доказательства разделов 15–17 объясняют корректность перехода во всём допустимом диапазоне. Эти способы дополняют друг друга.

22. Вопросы и ответы для защиты

  1. Почему размещения? Выбирается m различных цифр из десяти, и их порядок меняет число.
  2. Чем они отличаются от перестановок? Перестановка использует все элементы выбранного исходного множества; размещение из десяти по m может использовать только часть. При m=10 классы совпадают.
  3. Почему цифры не повторяются? Это условие задания; начальное размещение и каждый переход сохраняют различие.
  4. Почему запрещён первый ноль? Иначе запись не является m-значным натуральным числом; ноль внутри разрешён.
  5. Почему лексиграфический порядок? Для записей равной длины он совпадает с числовым и даёт возрастающий stdout без сортировки.
  6. Как формируется следующее размещение? Дополнение отсутствующими цифрами по убыванию, следующая полная перестановка, первые m позиций.
  7. Зачем убывающее дополнение? Оно ставит нас в конец блока полных перестановок с текущим префиксом; следующий шаг меняет префикс на непосредственный следующий.
  8. Как определить конец? Дополненная перестановка целиком убывает, поэтому индекс подъёма не найден. Последний префикс (9,8,...,10−m).
  9. Почему нет пропусков? Каждый шаг переходит к следующему блоку префиксов, а начало минимально.
  10. Почему нет повторов? Префикс строго увеличивается; его фильтрация не повторяет вызов вывода.
  11. Как проверяется пара? Два цикла по всем i<j до первого совпадения суммы с S.
  12. Почему достаточно одной? В условии стоит «хоть в 1 паре», то есть квантор существования, не требование ровно одной пары.
  13. Что происходит при m=10? Дополнение пусто, перебираются все 10! перестановок; после исключения 9! ведущих нулей остаётся 3265920 результатов для обеих сумм.
  14. Почему есть пороги? Без пары S=9 можно взять максимум одну цифру из каждой из пяти пар; для S=10 к четырём одиночным выборам можно добавить 0 и 5.
  15. Зачем включение-исключение? Независимо проверить количество при перекрывающихся событиях нескольких пар; в генератор оно не встроено.
  16. Как программа была проверена при разработке? Полные малые последовательности, два математических подсчёта для всех параметров, большие потоки, полный десятизначный эталон, CLI, ошибки stdout, два компилятора и санитайзеры.
  17. Почему C11? Достаточно фиксированных массивов и стандартных функций; ход алгоритма открыт для объяснения, C++ и библиотеки не нужны.
  18. Что с неверными аргументами? Полная проверка до перечисления; ошибка в stderr, код 2, stdout пуст. Повторы и смешанный --help запрещены.
  19. Какова сложность? O(A·(n+m²)) вычислений, дополнительно O(Qm) формирования вывода; память O(n).
  20. Почему не храним все числа? Для перехода нужно только текущее размещение; для подсчёта — один счётчик, для вывода — одна строка.
  21. Нужен ли Python для программы? Нет. Он использовался только независимыми проверками на этапе разработки. Чистовая сборка и запуск выполняются Clang напрямую либо через Makefile.
  22. Зачем два формата документации? README — основной Markdown-источник для GitHub и редактора, HTML — автономная визуальная версия с тем же материалом и встроенной математикой.
  23. Что делает make run ARGS="--digits 4 --sum 10"? При необходимости собирает программу, затем запускает её с указанными аргументами. Без ARGS запускается обычный режим по умолчанию.
  24. Какая часть условия остаётся неоднозначной? Исходная фраза не определяет однозначно длину и сумму дополнения. Программа реализует явно принятую модель, поддерживает обе суммы и частный случай m=10; этот выбор не выдаётся за уточнённое требование преподавателя.
